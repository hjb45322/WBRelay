# 方案 ・ 文案与术语统一

> 背景：2026-10-11 身份接管（`WBRelay-OSS` → `WBRelay`）后，界面与文档里同一个对象存在多个名字。
> 目标：定一套术语，并把整套可见文案补齐。
> 状态：**已执行（2026-10-11）**

---

## 一、术语标准

| 概念 | 统一用词 | 不再使用 |
|---|---|---|
| 本机这个转发网关 | **WBRelay** / **网关** | — |
| 网关分流的第三方 API 服务 | **供应商** | 「上游」不用来指供应商本身 |
| 供应商侧返回的数据 | **上游返回** | （仅此语境保留「上游」） |
| 上游服务面板与其服务 | **上游服务**；端口叫**服务端口** | 反代、上游项目、上游反代、上游端口 |
| 用量页 | **用量看板** | 用量成本（页签与标题统一） |

## 二、审计发现

| # | 问题 | 位置 |
|---|---|---|
| 1 | 同一对象 4 个名字：反代 / 上游项目 / 上游反代 / 上游服务 | 页签、页面标题、状态徽标、启停按钮、离线提示、toast、设置卡片 |
| 2 | 「上游」同时指*供应商*和*该面板* | 模型配置 hint（供应商）vs 设置页（面板） |
| 3 | 页签「用量成本」与页面标题「用量看板」不一致 | tab vs sec-title |
| 4 | 离线提示写死「点击▶ 启动反代」，与按钮文案不同步 | 反代页 |
| 5 | 内部注释仍写「用量成本页」「反代页」 | CSS / JS 注释 |
| 6 | README 写「供应商配置」页（实际页签叫「供应商」）、「上游反代等其它进程」 | README |

## 四、有意保持不动

- **实现层标识符与接口路径**：`loadUpstream`、`#pg-upstream`、`/api/upstream/*`、`upstream_*` 配置键。
  它们对用户不可见，改动面大（前后端 + 配置迁移），收益低、风险高。
- **上游服务面板自身的品牌文案**：iframe 里的内容属于上游项目，不在本项目范围。
- 已一致的文案（供应商 / 模型配置 / 设置 / 网关）。

## 五、验收

- 页签 = 供应商 · 模型配置 · 用量看板 · 上游服务 · 设置
- `dashboard.html` 中「反代」仅作为历史标识符（`upstream`）出现，不再出现在可见文案
- 1440×900 与 390×844 两档截图；页签在窄屏可横向滚动、不换行

## 六、产品命名标准（2026-10-12 定稿）

| 用途 | 定稿 | 说明 |
|---|---|---|
| 产品名 | **WBRelay** | 品牌；单独出现即指本工具 |
| 功能副标题 | **多供应商自动路由** | 核心功能一句话；完整表述「多供应商自动路由网关」 |
| 看板品牌 / 窗口标题 / 托盘 | `WBRelay · 多供应商自动路由` | 名字 + 功能，用户一眼知道它做什么 |
| 对外包名（PyPI / 仓库） | `wbrelay-gateway` | 品牌 + 功能；不再带 `-oss` |
| 版权 / 作者 | `WBRelay contributors` | `LICENSE` / `pyproject.toml` |
| 技术标识（**不改**） | import 包 `wbrelay`、数据目录 `%APPDATA%\WBRelay`、协议头与配置键 | 用户不可见，改动面大 |
| 历史标识 | `WBRelay-OSS` | **只**用于 2026-10-11 身份接管前的叙述，以及安全阀（拒绝指向该历史目录） |
| 历史工具 | `tools/switch-to-oss.ps1` | **已从公开发布内容移除**（2026-10-12，见 `docs/方案-开源发布阻断修复.md` §3.2/D3）：它是接管期的内部迁移工具，内含旧实例启停路径，可能绕过 R7 值守重启。内容保留在 Git 历史（`c056443`），仅用于历史追溯。 |
