## 0. 一句话

把当前「个人定制网关」**另起独立副本**，重构为可公开发布的标准工具。
**原项目全程冻结、零改动**，正在运行的 8789 实例与 Codex 会话不受任何影响。

## 1. 目标 / 非目标

### 目标

1. 产出可公开分发的独立项目：新目录、全新 git 历史、无私有信息
2. 保留已验证的核心逻辑（路由、冷却切换、SSE 透传、chat→responses 翻译、用量统计、catalog 生成）
3. 建立「不可能误伤本机与在用数据」的隔离保护机制
4. 达到标准开源工程基线：许可证、依赖声明、CI、测试分层、文档

### 非目标（红线，全程不做）

| # | 红线 | 强制手段 |
|---|------|---------|
| R1 | 不触碰 `%APPDATA%\WBRelay\`（实时数据） | 新项目默认数据目录改名 + `--data-dir` + 每阶段哈希断言 |
| R2 | 不触碰 `~\.codex\config.toml` 与 catalog | `--no-ide-inject` + IDE 接管默认关闭 |
| R3 | 不覆盖根目录 `WBRelay.exe` | 开发期从不向原目录打包 |
| R4 | 不改动原仓库 `<原项目目录>` | 新目录 + 全新 git，与原仓库零关联 |
| R5 | 不自动操作外部进程 | 外部进程（Codex / 上游服务 / CC Switch）重启、杀进程一律显式点击 |
| R7 | 网关重启走值守进程（2026-10-12 增） | `python tools/restart-gateway.py`（停 → 起 → 等就绪，脱离会话）；禁止裸 kill / 裸启动 |
| R6 | 只读引用 `<上游项目目录>` | 不写入、不注册、不启停 |

## 6. M1 · 独立项目 + 隔离开关（本计划的核心基础）

**目标**：让新项目在任何情况下都不可能读写到在用数据与 Codex 配置。

### 6.1 建项目

1. 按第 3 节规则复制源码到 `<项目目录>`
2. `git init` + 首次提交
3. 补 `.gitignore`：新增 `ide_backups/`、`*.bak_*`、`*.log`

### 6.2 四个隔离开关（本阶段唯一的代码改动）

| 开关 | 作用 | 技术要点 |
|---|---|---|
| `--data-dir` / `WBRELAY_DATA_DIR` | 覆盖数据目录 | `DATA` 在 `relay.py:53` **import 时即求值**，参数解析必须前置到常量定义之前，否则无效 |
| `--no-ide-inject` | 全局禁止改写外部 IDE 配置 | 一次堵住 4 条写 `~/.codex` 的路径：启动注入 `3931`、`POST /api/codex/sync` `2858`、`/api/ides/*/restart` `2918`、模型刷新 `3026` |
| `--readonly` | `POST /api/*` 一律 403 | 让 `tests/preview_readonly_server.py` 名副其实（当前它复用同一个 Handler，点保存照样写真数据） |
| 默认数据目录改名 | 新项目默认 `%APPDATA%\WBRelay-OSS\` | 从第一行代码起就不可能误读在用配置 |

### 6.3 验收（自动化断言，不靠人眼）

用 `--data-dir <临时> --no-ide-inject --port 18789` 启动一次，断言以下三处 **SHA256 与 mtime 前后完全一致**：

- `%APPDATA%\WBRelay\*`
- `~\.codex\config.toml`
- 根目录 `WBRelay.exe`

另需回归：不带任何参数启动 → 行为与重构前一致。

## 8. M3 · 架构拆分

**目标结构**

```
wbrelay/
  __main__.py     CLI：参数 / 单实例 / 启动退出
  paths.py        DIR / RES / DATA 解析（惰性，支持覆盖）
  settings.py     加载 / 原子保存 / 旧数据迁移
  routing.py      匹配 / 优先级 / 冷却
  upstream.py     转发 + SSE + chat→responses
  usage.py        记录 / 聚合 / 筛选
  catalog.py      Codex catalog 生成（内置模板）
  ides/{base,codex,opencode,dsh}.py
  integrations/{upstream,ccswitch}.py
  web/{server,api_*.py}
  gui.py          webview / tray（可选依赖，导入失败降级为浏览器模式）
```

**搬迁顺序**：纯函数（翻译 / usage / 匹配）→ 有状态（settings / 冷却）→ 最后拆 Handler。

**必须保持的语义**（每搬一块都要回归）：

1. 失败必切换
2. 配置保存即清冷却
3. 全败必报错（`realm=supplier:all_failed`）

## 14. 何时需要停机

仅在未来「决定真的换用它」那一刻：

1. 托盘退出旧 `WBRelay.exe`（让 config 正常 restore）
2. 启用新版本（迁移配置）
3. 确认无误后归档原项目

开发全程 **零停机、零影响**。
