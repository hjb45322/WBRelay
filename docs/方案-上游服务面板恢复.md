**历史版的问题（本轮逐条收紧）**：
① 转发 Cookie（全局 `net._wb_cookiejar` 跨会话共享登录态）；
② 用 `sub = parsed.path[len("/proxy-wb"):]` 直接拼 URL，路径穿越（`/proxy-wb/../../`）与外部绝对 URL 未拦；
③ 无请求体/响应体上限，`resp.read()` 可把超大响应整体读进内存；
④ 无超时、无句柄关闭，失败把 `str(exc)` 原样回显；
⑤ 上游在不在线都要连，面板关着也返回上游的 HTML。

## 三、实现：`wbrelay/web/api_upstream.py`

### 3.1 入口与开关

- `PROXY_ENABLED = True`（常量仍保留，供测试与状态接口引用）。
- 新增设置项 `upstream_proxy_enabled`（默认 **true**；**无界面开关** ——2026-10-14 按所有者要求移除了设置页那一行）。关掉时回到第三轮那套
  403 + `POLICY_PROXY_DISABLED` 策略说明；两种状态都有测试。
- 上游功能总开关 `upstream_enabled` 关闭 → 404（同历史语义）。

### 3.2 目标白名单（唯一出口）

- 目标只允许 `http://127.0.0.1:<upstream_port()>`，端口由现有 `upstream_port()` 解析。
- 子路径：从 `self.path` 去掉 `/proxy-wb` 前缀后，**先做三项判定再拼接**：
  1. 必须以 `/` 开头；
  2. 不允许 `..` 段（逐段 split 判定，不靠字符串包含）；
  3. 不允许出现 `://`、`//`、`%2f` 类编码与反斜杠（防绕过 / 畸形 URL）。
- **不接受任何外部/用户提供的目标**：不从请求头、请求体、query 里取 host/port；
  不跟随重定向到别的 host（`urllib` 默认不跟随，这里显式 `HTTPRedirectHandler` 拒绝并转为 502）。

### 3.3 请求头白名单

只转发 **`Content-Type`** 与 **`X-Panel-Token`**。
**不转发** Cookie / Authorization / Referer / Origin / Accept-Encoding / User-Agent 注入等；
`User-Agent` 固定写 `WBRelay/<version>`。Cookie jar **不启用**（历史版 `net._wb_cookiejar` 不再被引用）。

### 3.4 体积 / 超时 / 句柄

- 请求体：先看 `Content-Length`，超过 `PROXY_MAX_REQUEST_BYTES`（1MB）直接 413，**不读 body**；
  chunked / 超限的流式请求按 `Transfer-Encoding` 存在即拒。
- 响应体：`resp.read(PROXY_MAX_RESPONSE_BYTES + 1)`，多读 1 字节判定，超限抛 502
  （不整体读进内存，复用 `wbrelay.net.ResponseTooLarge` 思路但独立常量）。
- 超时 `PROXY_TIMEOUT_SEC = 15`；`try/finally` 一定 `close()`；失败一律 **502 + 脱敏文案**。

### 3.5 HTML 绝对路径改写

`Content-Type` 含 `text/html` 且子路径是面板根 `/` 时，做同历史版本的改写
（`getURL('/` → `getURL('/proxy-wb/`、`src="/`、`href="/` 等），其余内容**原样透传**。
改写只发生在服务端文本层，不进看板 DOM。

### 3.6 状态接口

`/api/upstream/status` 新增/调整只读字段：`proxy_enabled`（真实值）、`proxy_policy`（停用时才有）、
`proxy_url`（启用时的挂载前缀 `/proxy-wb/`）。启停 / 自启 / 守护相关字段**保持现状**
（`control_supported=False`、`autostart_supported=False`、`watchdog_supported=False`）。

## 四、看板（`dashboard.html`，改完跑 `tools/sync_dashboard.py`）

- 面板可用（`proxy_enabled` 且 `online`）时渲染
  `<iframe id="upstream-frame" src="/proxy-wb/" loading="lazy">`，高度自适应 + `min-height`；
  不可用时保留现有策略提示与 `upstream-offline`。
- 恢复 `wbAutologin(frame)`：iframe 加载后在同源 iframe 内找密码框，
  填 `localStorage.wb_upstream_pwd`（默认 `admin`）并调 `submitPanelLogin()`；
  **整段 `try/catch`**，任何异常静默降级为「请手动登录」，不抛错、不 toast 报错。
- 口令**不落盘、不写日志**：只从浏览器 `localStorage` 取；`/api/upstream/settings`
  收到 `wb_password` 依旧 `cfg.pop("wb_password", None)`。
- 顶部状态徽标继续显示「上游服务在线 / 离线 · 端口 8788」——语义不变。
- **不重命名**任何既有元素 `id` / `data-*`；新增节点用新 id。
- XSS：iframe 内容由上游提供，**一律当数据**；看板侧任何新增渲染都走 `textContent`
  或 `esc()`，不把上游返回内容拼进 HTML 属性。

## 七、`--readonly` 下的语义

`/proxy-wb` **不是** `/api/` 管理面：它是本机回环面板的只读呈现。只读模式下：
- 仍然只打 `127.0.0.1:<upstream_port>`、仍然只转发两个白名单头、仍然不落盘；
- 因此只读模式**允许**面板查看（`test_readonly_zero_write.py` R8 相应改为断言
  「只读下 POST /proxy-wb 不产生任何写盘」：POST 会被 `_browser_gate` 之后的
  「上游面板自身语义」处理，而 WBRelay 侧零写入由 R10 零写入探针统一保证）。

## 九、残余风险（写入 SECURITY.md）

1. **POST 会透传**：面板里的写操作（改上游自己的配置）会经本代理转发到上游。这是「面板可查看」的必然代价；WBRelay 不改写、不存储这些内容，也不因此启停任何进程。
2. **上游返回的内容由上游负责**：代理只做路径改写，不审查上游 HTML/JS。同源挂载意味着上游脚本跑在 `http://127.0.0.1:<本网关端口>` 这个源下——上游若被污染，理论上能读到同源的看板接口。缓解：网关只绑回环、`/api/*` 有 Host/Origin 门禁、`require_admin_token` 可兜底；这是「本机单用户」模型的既有边界。
3. **`X-Panel-Token` 会转发**：口令类凭据一旦被上游日志记录，不在本项目控制范围内。
4. **`127.0.0.1` 端口推断**：端口来自上游目录启动脚本解析（`upstream_port()`），解析不到退回默认 8788；指错目录会指错面板，但**不会**因此连到外部主机。
