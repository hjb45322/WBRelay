# 方案 ・ 数据保护与回滚

> 对应里程碑 M0。目标：任何时刻都能安全回到 2026-10-11 这个可用状态。
> 状态：待确认

---

## 一、快照范围

### 1.1 包含

| 类别 | 内容 | 说明 |
|---|---|---|
| 源码 | `<原项目目录>\` 全量（含 `.git`） | 保证能回到任意历史点 |
| 运行版 | `WBRelay.exe` | 含哈希记录 |
| 实时数据 | `%APPDATA%\WBRelay\` 全量 | 含 `settings.json` / `usage.jsonl` / `ide_backups/` / `backups/` |
| Codex 配置 | `~\.codex\config.toml` + `~\.codex\model-catalogs\` | 用于核对接管状态 |

### 1.2 排除

- `build/` `dist/` `__pycache__/` `*.pyc`
- `.upstream/`
- 其他与本项目无关的 Codex 目录（`sessions/` `logs_*.sqlite` 等，体积大且无关）

---

## 二、快照目录结构

```
<快照目录>\
  src\                    原项目全量（含 .git）
  exe\WBRelay.exe
  data\                   %APPDATA%\WBRelay 全量
  codex\config.toml
  codex\model-catalogs\
  manifest-before.jsonl   哈希清单（阶段开始）
  ROLLBACK.md             回滚步骤
```

**约束**：该目录必须在任何 git 仓库之外；`data/` 与 `codex/` 含明文凭据，永不分发、永不打包。

---

## 三、校验清单格式

`manifest.jsonl`，每行一个对象的 JSON：

| 字段 | 说明 |
|---|---|
| `path` | 绝对路径 |
| `size` | 字节数 |
| `mtime` | 修改时间（浮点） |
| `sha256` | 内容摘要 |
| `zone` | `P1` `P2` `P3` `P4` 之一 |

用途：阶段前后各采集一次，逐行比对。任一差异 → FAIL。

---

## 四、工具设计

| 工具 | 作用 | 只读性 |
|---|---|---|
| `tools/collect_manifest.py <输出>` | 采集 P1–P4 哈希清单 | 纯读 |
| `tools/verify_untouched.py <基线清单>` | 与当前状态比对，输出 PASS / FAIL | 纯读 |

两者都不带副作用，可在任意时刻运行。

判定规则：

| 情况 | 结果 |
|---|---|
| 全部一致 | PASS |
| 任一文件内容变化 | FAIL |
| 任一文件新增 / 删除 | FAIL |
| 仅 mtime 变化 | FAIL（同样说明被写过） |

## 五、回滚流程

### 5.1 场景 A：本项目把某处改坏了，但在用服务仍正常

1. 停止本项目实例
2. 按 `manifest-before.jsonl` 定位被改动的文件
3. 从 `_wbrelay-snap\20261011\` 对应位置复制回原路径
4. 重新采集清单，确认与基线一致

### 5.2 场景 B：在用服务异常

1. 确认在用实例状态：`Get-NetTCPConnection -LocalPort 8789 -State Listen`
2. 若配置被改：从 `codex\config.toml` 复制回 `~\.codex\config.toml`
3. 若数据被改：从 `data\` 复制回 `%APPDATA%\WBRelay\`
4. 重启在用 `WBRelay.exe`
5. 校验：`WBRelay.exe` SHA256 应为 `8665DC736CA72AFC0CD2C9DA1D22FD6913E27F957B894AA7E3FB158468ABE6BB`

### 5.3 场景 C：原项目源码被误改

1. `git -C <原项目目录> status` 查看差异
2. `git checkout -- .` 或从 `src\` 复制回

## 六、凭据处理规则

| 规则 | 说明 |
|---|---|
| 快照不入库 | 快照目录位于仓库外，且永不 `git add` |
| 快照不打包 | 不进入任何分发产物 |
| 快照不外发 | 不上传到任何云盘 / 仓库 |
| 用后处理 | 确认重构稳定后，可删除 `data\` / `codex\` 子目录，保留源码与 EXE |

---

## 七、演练要求

M0 完成时必须做一次**只读演练**（不实际替换）：

1. 运行 `collect_manifest.py` 得到基线
2. 运行 `verify_untouched.py` → 应 PASS
3. 人工抽查 `ROLLBACK.md` 中的复制命令能否定位到源文件
4. 演练不修改任何受保护对象

---

## 八、保留策略

| 时机 | 动作 |
|---|---|
| M0 完成 | 建立快照 |
| 每个里程碑结束 | 运行 `verify_untouched.py` |
| 发布准备 | 保留源码与 EXE 快照，可清理数据快照 |
| 正式切换后 | 归档原项目，快照转为长期存档 |
