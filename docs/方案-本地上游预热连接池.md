# 方案 ・ 本地上游预热连接池（ready queue）

> 状态：已完成（2026-10-21）
> 触发：WBRelay 到本机反代偶发 `WinError 10060`，单供应商被冷却后放大为 503。
> 目标：把正常请求路径上的新建 TCP 连接移到后台，避免瞬时本机连接失败直接变成用户可见故障。

---

## 一、问题与边界

2026-10-21 06:06:40，WBRelay 记录一次 `supplier:all_failed`：

- `elapsed_ms=21053`
- 错误为 `WinError 10060`
- 反代 `gateway.err.log` / `usage.jsonl` 在同一时段没有对应请求
- Windows 系统日志在故障前一分钟出现 `Tcpip 4227`，提示高速短连接下的本地端点复用限制

当前实现每个模型请求都由 `_supplier_send()` 调用 `urllib.request.urlopen()`，即每次重新建立 TCP 连接。流式上游响应还会主动发送 `Connection: close`，因此不能只靠 HTTP keep-alive 复用。

这里的目标是：

1. 正常请求到来时，优先领取一个**已经完成 TCP 建连、尚未发送请求**的连接；
2. 连接在后台持续补充，不在请求线程里临时 `connect()`；
3. 瞬时补连失败只影响后台队列，不直接冷却供应商；
4. 不修改反代、不修改 Windows TCP 参数、不牺牲流式输出。

这不是数学意义上的绝对零失败：如果反代进程、Windows TCP 栈或本机网络完全不可用，仍然会失败。目标是把正常高频使用下的瞬时 `10060` 从请求路径移除。

---

## 二、设计

### 2.1 新模块

新增 `wbrelay/localpool.py`，仅使用标准库：

- `LocalReadyPool`：按 `(scheme, host, port)` 维护 ready 连接；
- `open_local_request(req, timeout)`：本地上游 HTTP/HTTPS 请求入口；
- `LocalConnectError`：标记“请求发送前没有建立连接”的本地传输错误。

每个连接只用于一次流式请求；响应结束后关闭，不假设反代支持 keep-alive。

### 2.2 动态水位

默认参数：

| 参数 | 值 | 含义 |
|---|---:|---|
| `IDLE_LOW` | 4 | 空闲低于此值立刻扩容 |
| `IDLE_TARGET` | 8 | 常态至少保持 8 个 ready |
| `IDLE_BURST` | 12 | 活跃并发 ≥ 8 时提高到 12 个 ready |
| `IDLE_MAX` | 16 | ready 队列硬上限 |
| `CONNECT_TIMEOUT` | 2s | 后台建连上限，避免补连线程卡 20 秒 |
| `ACQUIRE_WAIT` | 10s | ready 为空时请求最多等待补连的时间 |

规则：

- 每次从 ready 队列取走连接后，立即通知后台补连；
- idle 低于 `IDLE_LOW` 时直接补到当前目标；
- active ≥ 8 时目标从 8 提到 12；
- 连接只按需创建，不在启动时一次性打满；
- 连接池用 `Condition` 等待，不使用忙轮询。

### 2.3 能力探测（避免饿死单线程本地服务）

并非所有本机 HTTP 服务都能承受空闲 TCP 连接。单线程 `HTTPServer` 会在第一个
idle 连接上阻塞，后续请求只能排队。因此 ready 队列不在第一次本地请求时立即启用：

- 第一次请求继续走原有 `_urlopen()`；
- 读取响应头的 `Server` 字段；
- 只有明确为 `wb-proxy/...` 的线程化本地上游才把 origin 标记为 poolable；
- 未识别的本地服务永远走原路径，不预热、不持有 idle 连接。

该标记是进程内的能力缓存，不写配置；上游重启或更换实现后，由新的首次请求重新探测。

### 2.4 连接健康检查

领取前检查 socket：

- socket 已关闭 → 丢弃；
- `select` 可读且有数据 → 说明状态不确定，丢弃；
- socket 仍可写 → 可领取。

领取后设置供应商请求超时；请求完成或异常都调用 `HTTPConnection.close()`，后台补新连接。

### 2.5 错误语义

- **补连失败**：后台退避重试，不冷却供应商；
- **请求领取前无法得到连接**：抛出 `LocalConnectError`，不把该错误当成上游供应商失败，不触发 60 秒冷却；
- **已经发送请求后失败**：保持现有供应商失败语义（冷却、切换、全败记录）；
- **413 / 400 / 404 / 422**：保持 `docs/方案-请求侧错误语义.md` 的请求侧语义；
- 现有三条核心语义不变：失败必切换、保存即清冷却、全败必报错。

### 2.6 集成边界

只在本地上游（`127.0.0.1` / `localhost` / `::1`）启用：

- `wbrelay/net.py` 增加本地请求入口与 `Server: wb-proxy` 能力探测；
- `wbrelay/web/api_v1.py::_supplier_send()` 按 URL 主机选择本地池或现有 `_urlopen()`；
- 非本地供应商、模型拉取、OpenRouter、面板代理等路径不改。

## 三、资源代价

每个 idle 连接会占用反代一个等待请求的 handler 线程。默认常态 8 个、突发最多 16 个；对当前本地反代可接受，但测试需观察线程数和退出清理。

连接池在进程退出时尽力关闭 ready socket；daemon 线程不阻塞退出。

## 四、测试清单

### 单元

1. 取连接后后台补回；
2. idle 低于低水位时扩容；
3. active 升高时目标提高；
4. 连接器抛 `WinError 10060` 时重试且不忙等；
5. 连接器恢复后 ready 队列补满；
6. 关闭后的连接被丢弃；
7. `LocalConnectError` 不触发供应商冷却。
