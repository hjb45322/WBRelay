# 方案 ・ 使用说明（入口与内容）

> 目标：让用户在界面里就能看到「怎么用」，不必去翻 README。
> 状态：已执行（2026-10-12）

---

## 一、入口选型

| 方案 | 取舍 |
|---|---|
| 第 6 个页签「说明」 | ✗ 页签已有 5 个（各 132px），再加会把窄屏顶栏挤到第二行，破坏刚收紧的顶部间距 |
| **顶栏「?」按钮 → 弹窗**（选定） | ✓ 不占页签宽度、随页签一起换行；弹窗可滚动放长内容；Esc / 点遮罩 / 「知道了」三种关闭方式 |
| 每页内联帮助 | 后续可选：按页签给「本页能做什么」的小提示 |

## 二、内容组织（弹窗五节）

| 节 | 内容 | 为什么放它 |
|---|---|---|
| 一、三步上手 | ① 供应商填接口地址 / API Key ② 模型配置「重新拉取」 ③ 让 Codex 连本机网关 | 新用户只关心「先点哪里」 |
| 二、五个页签各管什么 | 供应商 / 模型配置 / 用量看板 / 上游服务 / 设置，各一句 | 界面自解释不够，一句话最省事 |
| 三、路由规则 | 顺序尝试 / 失败冷却切换 / 全败报错（`realm=supplier:all_failed`）/ 保存即清冷却 | 与 `AGENTS.md` 第七节「核心语义」一一对应，避免用户靠猜 |
| 四、常见操作 | 拖拽排序、测速、编辑（掩码与粘贴）、模型启停、重启网关 | 覆盖日常点击路径 |
| 五、文件与排错 | 数据目录与各文件、端口顺延、Codex 起不来怎么办 | 出问题时第一眼要看的东西 |

## 三、维护规则

- 弹窗内容以**用户可见行为**为准；改功能时同步改这里（与 `CHANGELOG.md` 同批提交）
- 长文（安装、发布、架构）仍放 README / `docs/`，弹窗只放「上手 + 日常 + 排错」
- `id` 约定：按钮 `#btn-help`、遮罩 `#help-mask`、关闭按钮 `#btn-help-close`

## 四、验收

- 顶栏「?」按钮在页签条内最右，五个页签下位置一致
- 弹窗五节齐全、内容可滚动（实测内容 1036px / 视口 432px）
- Esc / 点遮罩 / 「知道了」三种关闭方式均可用
- 窄屏 351px：弹窗 323×611，完整落在视口内
- `python tests/check_dashboard_js.py` 全绿
