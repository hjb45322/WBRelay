# 方案 ・ 版本更新检测

> 触发：2026-10-14 所有者提出「加个版本更新检测」。
> 本方案先定边界与默认行为，**实现另起一次改动**（按项目规则：方案先行）。
> 状态：**待所有者确认**（一个决策点：默认是否允许「启动时自动检查」，见第四节）

---

## 一、为什么不能顺手加

这是一个**会主动外联**的功能，与本项目现有的公开承诺直接相关：

| 现有承诺（README / SECURITY.md） | 本功能的影响 |
|---|---|
| 「所有数据都在本机，**不上传、无遥测**」 | 更新检测本身不传用户数据，但**会**向 GitHub 发一次请求 —— 必须在文档里写清，不能含糊 |
| 「核心只用标准库」 | `urllib.request` 是标准库 ✓ 不破坏约束 |
| 「默认只监听 127.0.0.1」 | 与出站请求无关 ✓ |
| R5/R6（不碰外部进程 / 上游只读） | 更新检测不涉及 ✓ |
| 「开发/测试必须隔离」 | 测试必须**离线可跑**、不得真连 GitHub |

即：技术上很小，**承诺上很敏感** —— 所以要显式设计默认值。

## 二、设计

**数据流（只有一条）**

```
看板「设置」页 → GET /api/update（本机回环）
              → 网关向 `api.github.com/repos/hjb45322/WBRelay/releases/latest`（写作不带 scheme，避免触发发布门禁的 HOST 规则） 发一次 GET
              → 读 tag_name → 与 wbrelay.__version__ 比较 → 返回 {current, latest, has_update, url}
              → 看板显示一行结果（有新版时给 Release 链接）
```

**默认行为（保守）**

| 项 | 默认 | 说明 |
|---|---|---|
| 自动检查 | **关** | 不做任何后台轮询、不在启动时偷偷联网 |
| 手动检查 | **开** | 看板一个「检查更新」按钮，用户点了才发请求 |
| 超时 | 5 秒 | 超时/离线/被墙一律静默降级，不影响任何功能 |
| 发出去的内容 | 仅 HTTP 请求本身 | **不传**版本号、路径、供应商、用量、Key；只带一个固定 `User-Agent` |
| 收到的内容 | 只读 `tag_name` | 不下载、不安装、不改任何文件 |
| 结果落盘 | **不落盘**（只存在内存 + 看板显示） | 只读模式下同样可用 |
| 可关闭 | 配置项 `update_check`（`off` / `manual`） | `off` 时连按钮都不发请求（返回「已禁用」） |

## 三、接口与实现点

| 位置 | 内容 |
|---|---|
| `wbrelay/update.py`（新增） | `latest_release()` / `compare_versions()` / `check()`；只用标准库，5s 超时，异常一律吞掉并返回结构化结果 |
| `wbrelay/web/api_state.py`（或新增 `api_update.py`） | `GET /api/update` → JSON；遵循现有 Host/Origin 门禁与只读语义（只读模式下也允许，因为不写盘） |
| `wbrelay/static/dashboard.html` + 根 `dashboard.html` | 设置页加一行「检查更新」按钮与结果文案（**两处必须一致**，`tools/sync_dashboard.py` 保证） |
| `tools/sync_dashboard.py` | 无需改（沿用现有同步机制） |
| `tests/test_update_check.py`（新增） | 见第五节 |
| `docs/` / `README` | README 补一节「更新检测」；SECURITY.md 的「不上传」措辞补一句「检查更新是唯一出站请求，默认手动」 |
| `CHANGELOG` | 记为 **1.1.0**（新增功能，非补丁） |

## 四、待所有者确认（1 个决策点）

**默认是否允许「启动时自动检查一次」？**

| 选项 | 优点 | 代价 |
|---|---|---|
| **A. 只给按钮（推荐）** | 完全不动现有「不主动外联」承诺 | 用户不点就永远不知道有新版本 |
| B. 启动时检查一次 | 用户能及时知道新版 | 每次启动都会联网一次，需要改 README/SECURITY 的措辞，且要提供关闭开关 |

## 五、验收（实现时执行）

| # | 断言 | 方法 |
|---|---|---|
| 1 | 离线不报错、不阻塞 | 测试内 mock 掉 `urllib.request`，让 `urlopen` 抛 `URLError` / 超时 → 接口仍 200，`has_update=false` |
| 2 | 版本比较正确 | `1.0.2 < 1.1.0`、`1.0.2 == 1.0.2`、`v` 前缀、预发布后缀（`1.1.0-rc1`）用例 |
| 3 | **默认零自动外联** | 启动 → 不点按钮 → 断言 `urlopen` 调用次数 = 0 |
| 4 | `update_check=off` 时连按钮也不发请求 | 接口返回「已禁用」且 `urlopen` 未被调用 |
| 5 | 只读模式零写入 | `--readonly` 下检查更新 → 数据目录无任何文件生成 |
| 6 | 不泄露本机信息 | 断言发出的请求只有 1 个、URL 固定、headers 不含路径/版本/供应商 |
| 7 | 看板两份副本一致 | `python tools/sync_dashboard.py --check` |
| 8 | CI | 新增步骤纳入门禁；全程离线，不访问真实 GitHub |

## 六、明确不做

- 不做**定时轮询**、不做后台常驻检查线程；
- 不做**自动下载 / 自动替换 EXE / 自动重启**（那会直接撞 R7）；
- 不上报任何使用数据（不统计、不埋点、不含机器指纹）；
- 不引入第三方库（不装 `requests`）。
