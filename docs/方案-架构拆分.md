# 方案 ・ 架构拆分

> 对应里程碑 M3。目标：把单文件拆成有边界、可测试、可发布的包，且行为零变化。
> 状态：**已实现（M3，2026-10-11）**
> 修订（2026-10-11 身份接管）：默认数据目录名由 `WBRelay-OSS` 改为 `WBRelay`，下文涉及该目录名的描述按此读。

---

## 一、设计原则

1. **行为不变**：拆分是"搬运 + 收口"，不是重写逻辑
2. **可回退**：每一批搬迁都能独立回退，不产生"半拆状态"
3. **依赖单向**：下层不知道上层，禁止循环依赖
4. **入口不变**：`relay.py` 保留为入口，`start.bat` 与打包参数继续可用
5. **核心零依赖**：包内不引入第三方库；可选依赖只出现在 `gui.py`

## 三、模块职责与依赖方向

依赖只能**从上往下**：

```
            __main__
               |
      +--------+--------+
      |                 |
    web  -------------  gui
      |
  ides / integrations
      |
 routing / usage / catalog
      |
   settings
      |
   policy
      |
   paths
```

| 模块 | 职责 | 不允许做的事 |
|---|---|---|
| `paths` | 解析目录，提供路径常量 | 读写业务数据 |
| `policy` | 判断某动作是否被允许 | 执行业务动作 |
| `settings` | 配置读写、迁移 | 直接改 IDE 配置 |
| `routing` | 选供应商、冷却 | 发网络请求 |
| `usage` | 用量落盘与统计 | 改配置 |
| `catalog` | 生成模型清单 | 决定要不要写（由 policy 决定） |
| `ides/*` | 各 IDE 的读写实现 | 自行绕过 policy |
| `integrations/*` | 私有/外部项目适配 | 被核心强依赖 |
| `web/*` | HTTP 处理 | 直接访问文件系统路径常量 |
| `gui` | 窗口与托盘 | 被核心 import |

## 四、入口 shim

`relay.py` 保留，内容收敛为：

```
from wbrelay.__main__ import main
if __name__ == "__main__":
    main()
```

好处：

- `start.bat` 里的 `python relay.py` 不变
- `pyinstaller --add-data "dashboard.html;." relay.py` 不变
- 打包产物仍为单文件 `WBRelay.exe`

## 五、搬迁顺序

分 5 批，每批独立可回退，批间必须全绿。

| 批 | 内容 | 依赖 | 回归重点 |
|---|---|---|---|
| B1 | `paths` + `policy` | 无 | 隔离验收用例 1–7 全绿 |
| B2 | `usage` + `catalog` | paths | 用量聚合数值一致；catalog 生成结果与拆分前逐字节一致 |
| B3 | `routing` + `upstream` | paths | 三条核心语义；SSE 逐行透传；chat→responses 翻译 |
| B4 | `settings` + `ides/*` | policy | 原子写；接管/恢复；开关门禁 |
| B5 | `web/*` + `__main__` + `gui` | 全部 | 全部 API 与看板端到端 |

搬迁纪律：

- 先补该模块的单元测试，**再**移动代码
- 移动后立刻对照拆分前的行为，禁止"顺手优化"
- 每批结束跑完整隔离验收

## 八、frozen 兼容规则（必须保持）

```
if getattr(sys, "frozen", False):
    DIR = os.path.dirname(sys.executable)      # 仅用于旧数据迁移探测
    RES = getattr(sys, "_MEIPASS", DIR)        # 只读资源解包位置
else:
    DIR = os.path.dirname(os.path.abspath(__file__))
    RES = DIR
```

- 可写数据一律走 `DATA`
- 只读资源一律走 `RES`
- 打包命令基线：`pyinstaller --onefile --noconsole --name WBRelay --add-data "dashboard.html;." relay.py`

## 十、已实现的配置项（M4）

原本硬编码在本机路径 / 私有约定里的东西，全部改为**可配置 + 优雅降级**：

| 配置项（settings.json） | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `upstream_dir` | `WBRELAY_UPSTREAM_DIR` | 空 | 外部上游项目目录；**不再猜测任何路径** |
| `upstream_task` | — | 空 | 上游项目的 Windows 计划任务名；空则跳过计划任务操作 |
| `upstream_catalog_path` | — | 空 | 外部 catalog 文件路径（用于档案导入与倍率/显示名对齐） |
| `codex_provider` | — | `upstream` | Codex `model_provider` 名（改名会导致历史会话 not found） |
| `codex_aumid` | — | `OpenAI.Codex_2p2nqsd0c76g0!App` | Codex 桌面应用 AUMID，不同分发渠道可能不同 |

### 已清理的硬编码

| 原位置 | 原内容 | 现状 |
|---|---|---|
| `upstream_dir()` | `<上游项目目录>` 及两个猜测路径 | 已移除，仅认配置 |
| `_find_python_for()` | `<Python 3.9 目录>` / `<Python 3.12 目录>` / … | 已移除，仅用上游自带 python 与 PATH |
| `_load_upstream_catalog_map()` | 私有 catalog 绝对路径 | 改为 `upstream_catalog_path` |
| `_api_profiles_import()` | 同上 | 改为 `upstream_catalog_path`，未配置返回 404 |
| `CODEX_AUMID` | 常量 | 改为 `codex_aumid()` |
| `CODEX_PROVIDER_NAME` | 常量 | 改为 `codex_provider_name()` |
| `UPSTREAM_TASK` | 常量 | 改为 `upstream_task_name()`，默认空 |
| `CODEX_CATALOG` | `upstream-models.json` | 改为 `wbrelay-models.json` |

### 降级行为

| 场景 | 行为 |
|---|---|
| 未配置 `upstream_dir` | 上游管理功能整体不激活，状态接口返回空路径 |
| 未配置 `upstream_task` | 跳过计划任务查询/停止，仅按端口与进程判断 |
| `~/.codex/model-catalogs` 里没有 `relay-*.json` | `_load_relay_template()` 退化为扫描目录内任意 catalog；仍找不到则用最小条目（功能不变，档位展示略简） |
| 未配置 `upstream_catalog_path` | 倍率/显示名对齐功能关闭，其余不受影响 |

### 踩到的坑（已修正）

1. **模块级全局变量被邻接函数带走** —— 抽取工具原先以「下一个 def」为边界，
   会把夹在函数之间的全局变量一起搬走；已改为遇到下一个顶层语句即停止。
2. **多行赋值只搬首行** —— 已改为按括号配平确定语句范围。
3. **转口导入被误判为定义源** —— 自动补 import 工具现只认真正的定义点（def/class/赋值），
   并排除只做转口的模块。
4. **`_SERVER_PORT` 跨模块失效** —— 原先 `global _SERVER_PORT` 只会重绑本模块名字，
   下沉到 `state` 后统一改为 `state._SERVER_PORT = port`。
5. **`profiles._profiles_meta` 被 global 重绑** —— 直接 `from ... import` 会拿到过期引用，
   `net.py` 改为模块限定访问。
