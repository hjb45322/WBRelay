使用说明

WBRelay · 多供应商自动路由网关

一、三步上手

  1. 供应商：点右上「＋ 添加供应商」，填名称、接口地址（Base URL）、API Key → 保存即生效。
  2. 模型配置：点「重新拉取」拿到各上游的模型清单与倍率，再按需要逐模型启停（档位优先用上游返回，缺失由模型档案库补全）。
  3. 接客户端：内置四款（Codex / OpenCode / DSH / Crush）在「IDE 客户端接管」里点开关一键写入；其它客户端用同一行的「其他 IDE」卡片 —— 把它给的 Base URL 与 Key 填进客户端自己的配置即可。

二、五个页签各管什么

供应商
上游清单与优先级（拖拽排序 = 排前面的先用）；启停开关、测速、编辑、复制、删除。
模型配置
拉取模型、按分组启停（组内「全启用／全停用」）；页头的「IDE 客户端接管」卡片组与「其他 IDE」卡片也在这里。
用量看板
请求次数与成功率、Token 用量、平均耗时；按模型／供应商汇总与明细筛选。
上游服务
把外部上游的面板原样嵌进来看（同源代理，只做呈现）：服务状态、端口、内嵌页面与它的自动登录。网关自身不启停、不自启、不守护外部程序；在面板里的操作由那个面板自己执行。
设置
网络与路由、用量与统计、安全与访问、系统与集成、上游服务、配置文件位置。

三、路由规则（核心语义，不会变）

  • 按列表顺序尝试：已启用 + 未冷却 + 模型命中 的供应商优先用。
  • 请求失败即自动冷却并切下一个；冷却中的供应商会被跳过。
  • 全部失败才报错：返回最后一个错误，用量里记 realm=supplier:all_failed。
  • 保存供应商／设置会清空冷却表，立即恢复尝试。

四、常见操作

  • 拖拽卡片调整优先级。
  • 测速：请求上游 /models 计时，结果显示在按钮右侧（未测 → 测速中… → 123 ms／失败）。
  • 编辑供应商：API Key 回显为掩码，原样不动 = 保持原 Key，填新值即替换；名称／地址／Key 后都有「粘贴」按钮（走本机网关读剪贴板，不弹浏览器授权）。
  • 模型启停：模型配置页每个分组内单独开关，分组头会显示该组「已启用 n/N」。
  • IDE 接管：每张卡有「归属」一行，实时告诉你现在是谁在接管 —— WBRelay 接管中 / WBRelay 残留（端口不一致） / 其他工具或手工接管 / 未接管（每 5 秒自动刷新，被外部改过还会标「配置已被外部改写」）。开关打开＝备份并写入，关闭＝还原；改完点「↻ 重启」让客户端重新加载。
  • 给没内置的客户端：用「其他 IDE」卡片。地址点 ⧉ 复制；Key 平时打码，点进输入框可看真值并直接框选复制；「刷新」换一把新的（会二次确认，成功后自动复制到剪贴板）。
  • 重启网关：python tools/restart-gateway.py（值守进程执行，2–5 秒恢复，期间 Codex 会话会短暂中断）。

五、文件与排错

  • 数据目录 %APPDATA%\WBRelay：设置页「配置文件位置」有全部路径与一键复制。
  • 日志 wb.log；用量 usage.jsonl；模型档案 model_profiles.json；窗口大小 window.json。
  • 端口默认 8789；被占用会自动顺延（也可用 --port 指定）。把地址贴进浏览器时 http://127.0.0.1:8789/v1 会直接列出当前可用的模型。
  • 客户端拉不到模型：地址要填到 /v1；模型名照抄清单里的名字（大小写敏感）；没启用的模型会返回 503。
  • 协议范围：只讲 OpenAI 协议 —— /v1/chat/completions（多数客户端）与 /v1/responses（Codex）。不提供 Anthropic 的 /v1/messages，也没有向量／图片／语音接口。
  • Codex 起不来：多半是模型清单（catalog）缺字段 —— 在模型配置页重新拉取一次即可重建。
网关只监听 127.0.0.1，默认不做鉴权（Key 填什么都能连）；要真校验就在设置页打开「API Key 校验」。
